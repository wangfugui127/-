# 登录会话滑动续期

2026-10-14：解决原先登录满 2 小时后，即使持续操作仍会过期的问题。当前每个携带 Token 且认证通过的请求都会将 Redis 会话有效期重置为 2 小时，继续使用原 Token。连续 2 小时没有认证请求才自然过期；后台轮询也会续期。

## 代码与流程

- `AuthService.SESSION_TTL`：登录与续期共用的 2 小时有效期；登录响应 `expiresIn` 仍为 7200 秒，表示初始有效期。
- `BearerFilter`：读取会话 → 查询用户身份和 ACTIVE 状态 → 对现有 key 执行 EXPIRE → 创建 Actor → 继续请求。
- 只更新现有 key 的过期时间，不 SET 重建会话。已过期、未知 Token、禁用账户不续期；认证过程中会话已被删除则续期失败，返回 401。退出接口继续删除当前会话。
- Redis 或数据库认证故障维持 503。前端继续携带原 Token，无须新增刷新接口。

新增 5 项集成测试：

1. 将会话缩短到 30 秒/60 秒，再请求购物车和当前用户，验证两次都续期到约 7200 秒，用户 ID 保持不变。
2. 已过期和未知 Token 返回 401，Redis 会话不会重建。
3. 退出删除会话，旧 Token 再请求仍返回 401，不会重建。
4. 禁用账户返回 401，原短 TTL 不会续期。
5. 在真实用户查询后删除 Redis 会话，模拟读取与续期之间的退出/过期竞争；续期失败返回 401，不会重建。
